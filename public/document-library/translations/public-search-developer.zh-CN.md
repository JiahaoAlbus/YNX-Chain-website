## 直接回答

YNX Developer 涵盖测试网 RPC、SDK、合约、验证和 IDE 工程接口。YNX Testnet 使用 EVM 链 ID 6423 和 YNXT。兼容性限于经过直接测试的方法与构建产物，不涵盖每种以太坊工具或操作码。

## 安全起步

验证网络名称、链 ID、端点 TLS、发布身份和区块增长。使用仅用于测试网的账户，以及通过环境提供的部署者凭据。不要将密钥提交到源码，也不要依赖自动生成或默认的生产凭据。

源码提供 Hardhat 和 Foundry 配置、JavaScript 与 Python SDK 指南、网络辅助函数，以及合约验证工作流。在干净检出的代码中执行受限 IDE 和共识测试前，必须先生成 Solidity 构建产物。

## 合约发布条件

发布地址前，验证链 ID、链上字节码、源码与编译器设置、构造参数、小数位数、符号、授权主体和部署交易。在真实代币合约满足这些条件前，规范代币列表保持为空。

## 钱包与 AI

部署需要规范的钱包审阅和签名。开发工具或 AI 可以起草代码、测试或补丁，但不能持有用户密钥，也不能未经明确批准就部署。服务商与模型状态、上下文使用同意、成本、预览、应用或拒绝，以及审计必须始终可见。

## 当前状态

本地工具和产品候选版本已经存在。公开 IDE 部署、完整钱包集成、带签名的 macOS 与 Windows 分发、独立审计和公开容量，都需要单独证据。
