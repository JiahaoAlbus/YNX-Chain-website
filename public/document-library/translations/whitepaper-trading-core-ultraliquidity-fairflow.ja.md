# 取引コア、UltraLiquidity、FairFlow

## 要点

YNX には現在、稼働中の取引所、DEX、共有流動性ネットワーク、本番マッチングエンジンの証拠がありません。「UltraLiquidity」と「FairFlow」は、正確な取引場所の集約と、監査可能な注文処理という、候補設計の目標を表す名称です。厚い流動性、最良執行、公正性、スリッページゼロ、約定保証を主張するものではありません。

## 資産の境界

ユーザー資産を置ける場所は、ユーザーの Wallet、指定された取引所サブアカウント、ユーザーが管理する戦略金庫、承認されたカストディ事業者、承認されたプロトコルコントラクトに限られます。取引サービス、AI レイヤー、ブラウザー、分析エンジンは、シードフレーズ、秘密鍵、任意の出金権限、所有者変更権限、ユーザーが承認した範囲を超える委任を受け取ってはいけません。

すべての取引場所アダプターは、資産管理モデル、チェーン・ネットワーク、資産の識別情報、見積もりの出典、認証、注文種別、手数料、制限、法域、規約、保持期間、ヘルス、障害時の意味を宣言します。第三者の見積もりや残高には、プロバイダー、`asOf`、バージョン、該当する場合の対象範囲・信頼度、古い・利用不可の状態を表示します。それらが、正規の Wallet の所有権やチェーン決済の証拠を置き換えることはありません。

## 候補となる取引ライフサイクル

1. 承認済みの取引場所を見つけ、経済的に異なる資産をまとめることなく、資産識別子を正規化します。
2. 手数料、ガス、レイテンシー、板の厚み、情報源を明示し、時刻付きの見積もりと注文板の対象範囲を取得します。
3. 経路、価格への影響、失敗ケース、アローワンス・委任の使用、ユーザーの最悪時の引落額をシミュレーションします。
4. 総額、すべての費用、最小受取額または指値、有効期限、取引場所・資産管理、リスクを含む確認画面を表示します。
5. 製品、デバイス、アカウント、厳密な操作、上限、有効期限、nonce ドメインに結び付いた、正規の Wallet 承認を要求します。
6. 委任の範囲内だけで送信し、プロバイダーの受領確認を、執行と決済から分けて記録します。
7. 正式な情報源から、約定、手数料、残高、受領記録、例外を照合します。
8. 未使用の権限を解放し、技術的に可能な場合、取消、失効、紛争の証拠、緊急退出をサポートします。

## FairFlow のルール

候補となる FairFlow は、使用前に公開された決定的な優先順位ルール、隠れた注文並べ替えの禁止、未開示の自己勘定取引の禁止、秘密のスプレッドの禁止、仮装売買や架空の出来高の禁止、注文フローの対価の開示漏れの禁止、保護対象または無関係なユーザーデータに基づく優遇の禁止を要求します。また、受領時刻、正規化された注文、経路の決定、ユーザー承認、取引場所の応答、約定、手数料、決済参照の監査可能な記録が必要です。

非公開注文フロー、バッチ処理、オークション、MEV 保護、シーケンサーの裁量を提案する場合、その信頼の前提、漏洩リスク、検閲経路、同順位時の決定方法、時計の情報源、リプレイ時の動作、異議申立て手順を規定し、独立してテストする必要があります。暗号化やバッチ処理だけから「公正」を推定することはできません。

## UltraLiquidity のルール

流動性の数値は、取引場所、ペア、売買の側、板の深度帯、タイムスタンプ、執行可能数量、手数料、除外事項を示す必要があります。集約された板の厚みで、複製された流動性や経路を通じて参照される流動性を二重計上してはいけません。プロバイダーのタイムアウト、古い見積もり、買値が売値を上回るクロス状態の板、承認不足、資産管理サービスの停止、チェーン再編成、照合の不一致では、架空の板の厚みや成功を返すのではなく、利用不可または部分的な結果を返します。

マーケティングでは、期間、方法論、生データの出典系譜、ボット・テストの除外、サンプルの対象範囲、証拠 ID なしに、流動性、出来高、スプレッド、執行改善、約定率の統計を公開してはいけません。ペーパートレードとシミュレーターの結果は、その区分を維持して表示します。

## 手数料と運用成績

承認前に、該当するガス、取引場所の手数料、プロバイダー費用、計算・データ料金、サブスクリプション、管理手数料、ハイウォーターマーク方式の成功報酬を、それぞれ分けて開示します。未実現利益に手数料を課したり、スプレッドとして黙って組み込んだり、同じ利益に二重課金するために基準をリセットしたりしてはいけません。別途承認された運用金庫契約に別段の定めがない限り、ユーザーの損益はユーザーに帰属します。収益は決して保証されません。

## リスクと復旧

リスクには、市場損失、スリッページ、部分約定、古いデータ、取引場所の支払不能、資産管理の障害、スマートコントラクトの欠陥、オラクル操作、ブリッジ障害、制裁または法域による制限、鍵の侵害、決済の遅延が含まれます。キルスイッチは、安全な出金を妨げずに新規注文を停止しなければなりません。緊急退出は、誰が起動できるか、対象資産、遅延、費用、取引場所またはチェーンが利用できない場合の代替手段を定義する必要があります。

## 証拠と有効化ゲート

有効化には、レビュー済みの資産管理・委任契約、プロバイダーの承認、決定的なテストベクトル、リプレイ・改ざん・誤スコープのテスト、実際のサンドボックスまたは Testnet での約定、照合、負荷・障害テスト、セキュリティレビュー、法的区分、手数料の承認、サポート・紛争対応、公開リリースの証拠が必要です。それまでは、リリース状態は false のままです。
